DZasm project files and the annotation commands (DZasm V0.36 or later).

base/spell62.clt, base/spell63.clt   the un-annotated projects: which bytes are code, text, tables or data
annotate_bank62.cmd, ..._bank63.cmd  the dl / rem / dc / de / di commands: names, comments, constants, expressions
spell62.clt, spell63.clt             the annotated projects (generated by genasm; you can reload them in DZasm)
genasm.sh / genasm.bat               regenerate ../spell62.asm and ../spell63.asm
repro/                               small reproducers for DZasm problems (see ../docs/dzasm-issues.md)

Regenerate the sources (run from anywhere; set DZASM if dzasm is not on the PATH):
    sh genasm.sh
genasm copies base/*.clt over the annotated projects first, so the comments never pile up (DZasm adds a comment
every time a rem command is run). To change an annotation, edit the .cmd file and run genasm again.

The sources assemble with Mpm using the OZ V5 definition files in ../def:
    mpm -b -Idef spell62.asm      (from the repository root; or run verify.bat / verify.sh)
No post-processing is needed. The only workaround is for DZasm's masking of the DOR pointers
(see ../docs/dzasm-issues.md, point 1): the two application DORs are raw bytes with comments.
